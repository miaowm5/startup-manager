# StartupManager · 开机自启管理（浏览器配置 GUI）

Windows 上的开机自启管理工具：普通进程起一个本地 HTTP 服务，你在浏览器里增删改自启项；
登录 Windows 时自动运行，**保留命令行窗口**，方便看日志、随时关闭。

支持两类自启内容：

| 类型 | 说明 |
|---|---|
| **PowerShell 命令** | 任意多行命令，在独立控制台窗口中执行，输出实时可见 |
| **运行 exe / 打开文件** | 指定目标文件（绝对路径）+ 参数；一律交给系统默认程序打开（等价于在资源管理器里双击），不等待其退出 |

---

## 快速开始

1. **建议以管理员身份**运行 `dist/StartupManager.exe`（单文件版，推荐）：右键 →「以管理员身份运行」
   - 由管理员身份创建的计划任务，在普通权限下无法修改（会提示「拒绝访问」）；只查看/编辑配置可以不提权
   - 若构建时单文件版失败，`dist/` 里会是绿色目录版：解压 `StartupManager-green.zip` 后右键 `start.cmd` →「以管理员身份运行」
2. 浏览器会自动打开配置页（形如 `http://127.0.0.1:8767/?t=<随机token>`）
3. 点「+ 新建自启项」，填 PowerShell 命令或 exe 完整路径，保存并生效

关掉那个控制台窗口就停止服务，**已注册的自启项不受影响**。

> 下次开机：不用你手动开这个工具，Windows 会按计划任务直接拉起每个自启项。

## 功能

- 列表总览：按登录延迟从早到晚排列，显示类型、命令摘要、延迟、权限、上次运行结果、是否已生效
- 一键启停（对应计划任务的 Enable/Disable，不删除配置）
- **立即运行**：不用重启就能验证窗口是否弹出、路径是否正确（会开一个独立控制台窗口）
- **脚本预览**：显示真正会被执行的内容（生成的 `run.ps1` / `run.cmd`），可审计
- 日志：就是登录时弹出的那个控制台窗口本身（不落盘，避免日志无限增长）；需要留档可在命令里自行重定向
- 延迟启动（0–600 秒）：等桌面/网络就绪，避免登录瞬间失败
- 运行级别：普通权限 / 最高权限（修改由管理员创建的计划任务需要管理员；「最高权限」项登录时还会以提权身份运行）
- 漂移检测：任务被人手工删了/禁用，界面会标红提示，点「重新同步」自愈；脚本模板升级或程序被移动时启动会自动修复

### 支持的文件类型

exe 类型的项目不再区分「直接执行」和「用默认程序打开」：保存后**一律**交给系统默认程序
（ShellExecute，等价于在资源管理器里双击），所以任何文件都能填，且不等待目标退出。

| 文件 | 说明 |
|---|---|
| `.exe` / `.com` | 由系统直接拉起，行为和双击一致（含清单里的 UAC 要求） |
| `.bat` / `.cmd` | 交给 `cmd.exe` 执行，会得到自己的控制台窗口 |
| `.lnk` / `.xlsx` / `.docx` / `.pdf` / 图片等 | 交给系统关联程序打开，不等待其退出 |
| `.ps1` | 能保存，但默认关联通常是记事本 —— 请改用「PowerShell 命令」类型 |
| 无扩展名 / 其他 | 由系统按关联打开；没有关联程序时会在登录后报错 |

## 原理

```
浏览器 ──HTTP(仅127.0.0.1, token)──▶ StartupManager 服务
                                        │
                                        ├─ config.json（唯一事实源）
                                        ├─ 生成 items/<id>/run.ps1 | run.cmd
                                        └─ 注册计划任务 \StartupManager\<id>
                                                │ 登录时触发（交互式令牌）
                                                ▼
                                      StartupManager --run <id>（控制台宿主）
                                                │
                                                ▼
                                      powershell.exe -File run.ps1
                                      或 cmd.exe /c run.cmd
```

关键取舍：

1. **用计划任务而不是 `Run` 注册表键**：能表达延迟、电池条件、失败重试，能查真实状态；`Run` 键这些全都没有。
2. **用户命令落到脚本文件，而不是拼进任务命令行**：绕开 cmd 引号嵌套与长度限制，编码可控，且可预览。
3. **`LogonType=InteractiveToken` + 任务不隐藏 + 控制台子系统宿主**：三者缺一，窗口就可能不出现或不可见。
4. **任务参数显式设置**：`ExecutionTimeLimit=PT0S`（否则 72 小时强杀）、允许电池启动、允许多次触发去重。

### 为什么"开机自启"实际是"登录后自启"

登录前（会话 0）没有交互桌面，控制台窗口即使创建也看不见、点不到。
所以可见控制台的项只能用登录触发 —— 这是 Windows 的语义，不是实现取舍。

## 命令行

```
StartupManager.exe                    启动配置服务并打开浏览器
StartupManager.exe --data-dir <目录>  便携模式：数据跟着程序走
StartupManager.exe --resync           重新生成脚本并同步全部计划任务
StartupManager.exe --clean-missing    清理目标已不存在的失效项（任务 + 配置）
StartupManager.exe --run <id>         以控制台宿主身份运行某项（计划任务调用，勿手工用）
StartupManager.exe --run-now <id>     直接运行某项并在当前控制台看输出（人工测试用）
```

停止服务：**关掉那个控制台窗口即可**（或在任务管理器结束该进程）。
启动时若已有实例在运行，再次双击 exe 会直接打开已有实例的配置页。

界面上的「直接运行」按钮等价于 `--run`：它走的是和登录自启**完全相同**的脚本与宿主，
只是立刻执行一次，并在独立控制台窗口里显示输出。

## 数据目录

默认 `%LOCALAPPDATA%\StartupManager`（便携模式可用 `--data-dir` 改）：

```
config.json                 配置（含启用状态、上次运行记录）
config.json.bak             上一次的备份
server.json                 运行中的端口与 token（关闭后删除）
items\<id>\run.ps1|run.cmd  实际执行的脚本（UTF-8 BOM / chcp 65001）
items\<id>\last-run.json    最近一次运行结果
logs\app.log                服务自身日志（超过 2MB 自动轮转）
```

## 安全说明

一个"能在本机写任意开机命令"的本地 HTTP 服务，天然是持久化接口，所以做了这些：

- 只绑定 `127.0.0.1`，绝不监听外网
- 启动生成 256-bit 随机 token，URL 带入后立刻换 Cookie 并从地址栏抹掉
- 校验 `Host`（防 DNS rebinding）与 `Origin`；不开 CORS
- 所有变更请求要求自定义头 `X-SM-Request: 1`（跨站无法伪造，天然抗 CSRF）
- 严格 CSP，前端不使用 `innerHTML` 渲染用户输入
- **程序不自动提升权限**：查看/编辑配置不需要提权；修改由管理员创建的计划任务需要管理员，程序会明确提示并以友好文案停止，不会偷偷 UAC。服务本身只监听 `127.0.0.1` 且带 token，即使以管理员身份运行也不对外网开放

## 已知限制

| 限制 | 说明 |
|---|---|
| 登录后才触发 | 见上；登录前的自启项不会有可见窗口 |
| 非管理员运行 | 可以新建和管理自己创建的任务；由管理员身份创建的任务无法修改（拒绝访问），程序会给出统一提示并停止后续写入，需以管理员身份重新启动 |
| 关闭窗口能否杀净目标进程 | exe 类型由 `start` 拉起，目标运行在自己的控制台/进程里，关掉启动器窗口不会回收它；PowerShell 类型的目标进程共用同一控制台，会被一起终止 |
| 移动程序目录 | 计划任务记录绝对路径，移动后点一次「重新同步」 |
| 多用户 | 任务注册为"当前用户登录时"，不覆盖其他用户 |
| 杀软误报 | 自启 + 本地服务 + 写计划任务的行为组合敏感，正式分发建议代码签名 |
| 单文件版 | Node SEA 注入，属实验特性；构建失败会自动回落到绿色目录版 |

## 常见问题

### 所有任务都启动后，本工具会在后台残留吗？任务依赖它吗？

**不残留，也不依赖。**

- 本工具只在你说「打开配置界面」时运行。关掉那个控制台窗口就彻底结束，不留后台进程。
- 每个自启项是**独立的计划任务**，登录时由 Windows 任务计划程序直接拉起
  `StartupManager.exe --run <id>`，跟配置界面是否开着完全无关。
- 那个 `--run <id>` 宿主进程只在任务运行期间存在：命令结束后，如果勾了「结束后保留窗口」，
  它会停在那里等你按键（窗口才留得住），按键/关窗后进程退出；没勾则立即退出。
- 所以：关掉 GUI → 没有任何本工具进程；任务仍在跑 → 只有该任务自己的进程树。

### 把 exe 删了，对应的自启项会自动消失吗？

**不会自动消失**，会残留一个必然失败的启动项 —— 但这不会影响系统，只是每次登录多弹一次报错窗口。

实际情况：

- 计划任务 `\StartupManager\<id>` 仍然存在，登录照常触发；
- 宿主进程启动后发现目标文件不存在，会打印「目标文件不存在：<路径>」并等待按键（若勾了保留窗口）；
- 配置里的项目也不会自动删除。

现在的处理方式：

- 列表里该项目会标红「**目标失效**」，并提示「登录后任务仍会触发并失败」；
- **顶部会出现「清理失效项 (N)」按钮**：一键删除所有目标已不存在的项目，连带移除计划任务与配置；
- 命令行等价物：`StartupManager.exe --clean-missing`；
- 只想删单个：点该项目的「删除」。

打不开界面时的手动清理：

```powershell
# 只删某个任务
Get-ScheduledTask -TaskPath '\StartupManager\' -TaskName '<id>' | Unregister-ScheduledTask -Confirm:$false

# 整段清理（所有本工具注册的任务）
Get-ScheduledTask -TaskPath '\StartupManager\*' | Unregister-ScheduledTask -Confirm:$false

# 连配置一起清掉
Remove-Item -Recurse -Force "$env:LOCALAPPDATA\StartupManager"
```

### 如果把本工具自己的 exe 删了/挪走了呢？

- 计划任务里记录的是**绝对路径**，登录时会因为找不到文件而失败（不会自动删除任务）；
- **放回原路径** → 立刻恢复，无需任何操作；
- **换到新路径** → 打开新位置的程序，列表会提示「程序位置已变化，需要重新同步」，点一次「重新同步」即可把全部任务改指到新路径；
- **彻底不要了** → 用上面「整段清理」两行命令，再删掉数据目录。

## 开发与构建

```bash
node src/main.js --dev            # 开发态（直接读 src/ui 下的前端资源）
node test/smoke.js                # 端到端 API 测试（需先以 SM_FAKE_TASKS=1 起服务）
node test/permission.js           # 权限不足时的行为（打桩，不碰真实计划任务）
node build/build.js               # 产出 dist/app.cjs、绿色目录版、单文件版
```

测试相关环境变量：

| 变量 | 作用 |
|---|---|
| `SM_DATA_DIR` | 覆盖数据目录 |
| `SM_FAKE_TASKS=1` | 不真正操作计划任务（受限环境跑全链路） |
| `SM_TOKEN` | 固定 token（便于自动化测试） |

单文件版依赖 `npx postject` 注入 SEA blob，首次构建需要联网；失败不影响绿色目录版。

## 故障排查

| 现象 | 处理 |
|---|---|
| 浏览器打不开 | 用启动时打印的完整地址（带 `?t=`）；token 不匹配会返回 401 |
| 保存时报"计划任务注册失败：拒绝访问" | 该任务多半是之前用管理员身份创建的，普通权限改不了。程序会给出统一提示并停止后续写入；关掉本程序，右键「以管理员身份运行」后重试 |
| 登录后没反应 | 任务计划程序里看 `\StartupManager\<id>` 的"上次运行结果"；确认"只在用户登录时运行" |
| 窗口一闪而过 | 勾选「结束后保留窗口」；exe 类型等价于双击，启动器窗口拉起目标后立即退出属正常，目标的窗口不受影响；也可看 `items\<id>\last-run.json` 的退出码 |
| 中文乱码 | 项目用 PowerShell 类型（脚本自动带 BOM）；exe 自身的输出编码不受本工具控制 |
| 端口被占 | 会自动换随机端口，看控制台打印的地址 |
